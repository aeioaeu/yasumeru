# やすめる

**父が育休を取ると、世帯のお金がどう動くか**を1本の時間軸に並べる Web ツール。

育休のお金は、制度が複雑なうえに効くタイミングがバラバラで、
先が見えないまま取るかどうかを決めることになりがち。
見えるようにして、憂いを減らして**男性が育休を取りやすくする**ための道具。

**取りにくさはお金だけの話ではない**ので、
「同じ立場の男性がどのくらい取っているか」も出している。
比べて競うためではなく、「自分だけじゃない」と分かるため。

**取りにくさは、まわりの目のこともある。** 会社の側にも助成の仕組みがあること、
不利益な扱いが法律で禁じられていること、相談先があることを事実として置いている。
**説得のための材料としては書いていない**（申請するのは会社であって本人ではないし、
「会社に教えてあげましょう」は本人に負担を移すことになる）。

## いまはここまで（MVP・1画面）

**画面に出しているのは1つだけ。**「二人とも家にいる間、世帯の手取りはいくらか」。
**スクロールなしで1画面に収まる**ところまで削ってある。

```
出産予定日・二人の月給・育休の長さ（ボーナスは扱わない）
        ↓
二人とも家にいる間の世帯の手取り（＋いつもの何%・取らない場合・内訳・3年の差）
        ↓
目安であること／できないこと・前提・出典（畳んである）
```

一度は16節あった。月ごとの動き、振り込みまでの空白、書類に載る年収、保育料、
ふるさと納税、ほかの男性の取得、会社への助成、法律、書類の期限——どれも意味のある事実だが、
**一度に並べたせいで、どこから読めばいいか分からなくなった。**

| いつ | 字数 | 高さ（幅390px） |
|---|---|---|
| 全部を展開して読ませていた頃 | 9,114字 | 20画面 |
| 畳んで並べ替えたあと | 4,292字 | 11.7画面 |
| 節を4つに削ったあと | 1,516字 | 4.2画面 |
| **いま（1画面）** | **約600字** | **740px＝1画面** |

**外したのは画面だけで、計算は全部残っている。** `calc.js` は保育料の所得割額も
ふるさと納税の枠も振り込みの予定も出し続けているし、`test.mjs` の79件もそのまま通る。
戻すのは表示を書くだけ。

### 1画面に収めるために決めたこと

| 決めたこと | なぜ |
|---|---|
| **入力は4つだけ**（出産予定日・二人の月給・育休の長さ） | これで答えは出る。40歳以上（介護保険料）だけ畳んだ中に置いてある |
| **月給は万円単位で受け取る** | `500000` は桁を数えないと読めない。そもそも**社会保険料は等級表・住民税は自治体で変わるので、一円単位の精度は出せない**。入力の粗さを、出せる精度に合わせた |
| **出す額も全部 0.1万円単位**（`61.6万円`） | 入力が万円なのに答えを1円まで出すと、**持っていない精度を主張する**ことになる |
| **二人の月給は、横に2つか縦に2つ。斜めに置かない** | 日付と月給2つを1つのグリッドに並べると、幅しだいで折り返しの位置が変わり、**「日付・あなた」「パートナー」**の2行になって二人の欄が斜めに並ぶ。月給2つを `.pair` に閉じ込めて、日付は行を独占させた |
| **ボーナスは扱わない** | 入力を1つ増やしても答えが確からしくならない。**下の「ボーナスを外した」を参照** |
| **人ごとの内訳をやめ、足し引きだけ残す**（給付と手当金 ＋ お給料 − 引かれるもの） | 「この数字は何なのか」は足し引きで伝わる。誰の分かまでは1行に収まらない |
| **差額は1行**（3年で見ると 二人合わせて +13.5万円） | 差額を入口にしないという線は守りつつ、隠しもしない |
| **免責は「責任を負えない」の一文だけ出す** | 消してよい種類の文ではない。理由と一覧のほうを畳む |
| **スライダーの直下の結果表示と、底の固定バーをやめた** | 入力と結果が同時に見えているなら要らない。**1画面に収まったことで消せた仕掛け** |

**二人の欄が横に並ぶ下限は 340px あたり**（`.pair` の `minmax(140px, 1fr)`）。
そこを割ると縦に2つ積む。**見出しの行は `subgrid` で二人ぶん共有**してあるので、
片方のラベルだけ折り返しても欄の高さはずれない（`subgrid` の無いブラウザでは
共有されないだけで、並び自体は壊れない）。

**基準にした高さは 745px**（iPhone 15 で Safari のバーを引いたときの可視高さ）。
390×844 の端末高ではなく、実際に見えるほうで測っている。

**iPhone SE（375×667）では 100px ぶんはみ出す。** ここを詰めるには内訳か3年の差を
落とすことになるので、**そこまでは削っていない**。

`.p-salary` は画面に、`.p-bonus` などは畳んだ中にある。どちらも `data-role` で括ってあるので、
`readPerson()` は役割で引く（場所を問わない）。

### ボーナスを外した

**入力から消して、計算にも入れていない。**

理由は入力が1つ減るからではなく、**入れても答えが確からしくならない**から。
育休中にボーナスが出るかどうか、出るとしていくらかは会社ごとにまったく違う
（部署の平均にする、期間で割る、一律で減らす、そもそも出ない）。
決まったルールがないので「いつもの何%か」を入力してもらう形にしていたが、
**その既定値（0%）が結論を左右していた**（上の「育休の長さと、3年で見た差」）。

外したことで数字はこう動く（母40万・父50万・育休1か月）。

| | ボーナスあり | ボーナスなし |
|---|---|---|
| 二人とも家にいる間の手取り | 592,090円 | **616,074円**（+4.1%） |
| 3年で見た差 | +13.5万円 | **+8.5万円** |

**手取りが上がって見えるのは、前年のボーナスに乗っていた住民税が消えるから。**
ボーナスがある人にとっては、実際の住民税と所得税はここで出る額より重い。
**画面の「出していないもの」にそう書いてある。**

### 戻す順

戻す基準は、**画面の外に置いておくと損をする度合い**。

| 順 | 何を | なぜその順か |
|---|---|---|
| 1 | 月ごとの手取り（表で。折れ線は「何月がいくら」に答えない） | 「いつが一番きついか」は、金額の次に聞かれる |
| 2 | 給付金が振り込まれるまでの空白 | 知らないと現金が足りなくなる。**期日のある話** |
| 3 | 書類に載る年収（源泉徴収票・住宅ローン） | 気づくのが申し込みの後になりやすい |
| 4 | 保育料・ふるさと納税 | 効くのが1年以上あとなので、いま知らなくても間に合う |
| 5 | ほかの男性の取得・会社への助成・法律・書類 | 数字が動かない。読みたい人が読めばいい |

**1つ戻した時点で1画面には収まらなくなる。** そのとき「1画面」を捨てるのか、
畳んだ中に入れるのか、別のページに分けるのかを決める——**戻すたびに決め直す**ことにしてある。

## 何を固定して、何を動かすか

**動かせるのは父の育休の月数だけ。** 母は制度の上限まで取るものとして固定する。

```
出産予定日
   │
   ├─ 母  産前6週 ─ 産後8週 ─ 育児休業（子が1歳に達する日の前日まで）
   │                          ↑ 両シナリオで同じ。だから差額に効かない
   │
   └─ 父  ■■■■ N か月（生まれた日から）
                ↑ ここだけが2つのシナリオの違い
```

母を**両方のシナリオに同じだけ載せている**。理由は2つある。

1. **産後8週間は就業させてはならない**（労基法65条）ので、母にとっての「育休を取らない」は
   通常勤務ではない。母を片方にしか載せないと、産休分の落ち込みまで父の育休のせいに数えてしまう。
2. **保育料の階層・ふるさと納税の上限・書類に載る年収は、差ではなく絶対値で決まる。**
   差がゼロでも、載せないと世帯の水準が嘘になる。

母の期間は「出産日（産前休業の末日）＋産後休業＋育児休業で最大1年」という制度の上限から出す。
産後休業が8週あるので、**育休そのものは約10か月**になる。
「1年休む」と「育休が1年」は別物で、ここを取り違えると2か月ずれる。

1歳6か月・2歳への延長は扱わない。不承諾通知などの要件があり、取れるかを事前に決め打ちできない。

## 一番効く分岐

**出生後休業支援給付金（13%の上乗せ）の配偶者要件は、父母で非対称になっている。**

| | 本人の対象期間 | 配偶者要件 |
|---|---|---|
| **父** | 出生日〜8週を経過する日の翌日 | 母が出生日の翌日に産後休業中なので、「配偶者の育児休業を要件としない場合」に該当して**自動的に満たされる** |
| **母** | 出生日〜**16週**を経過する日の翌日 | **父が出生日から8週以内に通算14日以上**取っていることが要る |

つまり**父が育休を取らなければ、母の13%も出ない。**
世帯では 13% × 28日 × 2人分が父の判断に連動する。

例（母 月給40万・父 月給50万）だと、二人合わせて約11万円がここで決まる。
13%は最大28日ぶんなので、**この額は育休を何か月取っても変わらない**。

### 育休の長さと、3年で見た差

同じ例（母 月給40万・父 月給50万・ボーナスなし）で、育休の長さごとの
「3年で見た世帯の差」はこうなる。

| 父の育休 | 3年の差 |
|---|---|
| 1か月 | **+8.5万円** |
| 2か月 | +6.3万円 |
| 3か月 | +4.6万円 |
| 6か月 | −6.9万円 |
| 12か月 | −85.9万円 |

**符号が変わるのは3〜6か月のあいだ。** 非課税の給付・社会保険料の免除・13%の上乗せが
前半に集中していて、そのあとは給与を失う分が上回っていく。

**ここは、ボーナスを外したことで変わった。** ボーナスを入れていた頃は
（父150万・母120万、育休中の支給0%として）こうなっていた。

| 父の育休 | 3年の差（ボーナスあり） |
|---|---|
| 1か月 | +13.5万円 |
| 2か月 | **−38.1万円** |
| 3〜6か月 | −36〜−40万円 |
| 12か月 | −170.4万円 |

**1→2か月で符号が変わっていたのは、2か月目にボーナス月が入って、
そのボーナスを丸ごと失う形になっていたから。** つまりあの段差は制度ではなく、
「育休中はボーナスが出ない」という**入力の既定値**が作っていた。
会社ごとにまったく違うところを既定値で決め打ちして、それが結論を左右していたことになる。

既定は**1か月**のまま。男性の48.9%が1か月未満なので実際の入口に近い、という理由は変わらない。
ただし**「1か月だけがプラス」という理由は、もう成り立っていない**（1〜3か月がプラス）。
既定をどこに置くかは、置き直す余地がある。

## 画面の作り

**出すのは「二人とも家にいる間、世帯の手取りはこのくらい」。**
父の育休は生まれた日から始まるので、その間母は産後休業中。
母には出産手当金（標準報酬日額の2/3）、父には育児休業給付（67%＋13%）。
**どちらも非課税で社会保険料も止まる**ので、額面の何割という数字より手取りは残る。

**大きい数字には、いつの話かと、比べる相手と、内訳をつける。**
数字だけ大きく出しても「それが何の額なのか」は伝わらない。順番も決めてある。

| 順 | 何を | 何のため |
|---|---|---|
| 1 | **いつの話か**（あなたの育休Nか月のあいだ・パートナーも休業中） | 期間が分からないと、額の大小を判断できない |
| 2 | **額** | 答え |
| 3 | **内訳の1行**（給付金と手当金 ＋ お給料 − 税・社会保険料） | 「手取り」の中身を開いて見せる |
| 4 | **比べる相手を2つ**（ふだんの月／取らない場合） | 高いか低いかは、比べる相手がないと決まらない |
| 5 | **3年の合計** | 差額は入口にしない。答えを見たあとに1行 |

**比べる相手は、割合や差だけでなく額そのものを並べる。**
以前は「いつもの 88%」というバッジと「取らない場合は◯◯円」という文が
隣り合っていて、**基準の違う2つの比較がどちらもラベルなしで並んでいた**。
いまは2行の表にして、行の見出しが「何と比べているか」、右が「その額」、
最後が「いまとの関係」になっている。どちらの行も**主語は「いま」**で揃えてある。

内訳は**同じ overlap 期間で平均を取ってから足し引き**している。
画面の上の足し算が合わないと、そこで読むのが止まる。

**合計の差額を入口にしない。** 開いて最初に大きな数字が目に入る作りにしていた時期があったが、
憂いを減らすのが目的なのに恐怖から始まっていた。差額は答えを見たあとの1行に置いている。

読み手は30歳前後を想定している。普段使うアプリの見え方に寄せて、

- スマホで**スクロールせずに読み終われること**（横スクロールも作らない）
- 入力を動かすと、その結果が**同じ画面の中で**変わること
- 税理士に相談しにくい人が読めること（専門用語には必ず言い換えを添える）
- センシティブな時期なので、押しつけず、決めつけないこと

を優先した。「損」「得」は強調せず、育休を取らない選択も否定しない書き方にしている。

### 万円で出す。ただし足し算は合わせる

**画面の額は全部 0.1万円（1,000円）単位。** 入力が万円単位なので、
答えを1円まで出すと持っていない精度を主張することになる。

**丸めると、内訳の足し算が合わなくなる。** 780通りで試したら36%で合わなかった
（ずれは必ず 0.1万円）。`balance()` がその端数を**1つの項に寄せて**、
画面の足し算が必ず合うようにしてある。寄せる先は
**「寄せても元の額から一番離れない項」**を毎回選ぶ（ずれは最大1,000円）。
このことは画面の「計算の前提」にも書いてある。

**丸め方を額で変えない。** 「100万円を超えたら整数」のような手加減を入れると、
`120 + 30 − 46` が `105` にならなくなる。全部 0.1万円単位で通す。

**差も、出ている数字どうしの引き算で出す。** 丸める前の額から出すと、
画面の `61.6 − 61.2` と注記の `0.5万円` が食い違うことがある。

540通り（月給 20〜200万 × 15〜150万 × 育休1〜12か月）で、
**画面に出ている数字だけで足し算と引き算が合うこと**を確かめてある。

### 読み手を「父」と呼ばない

**メインの読み手は、これから父になろうとしている男性。** まだ父ではない。
出産予定日は未来だし、育休を取るかどうかもこれから決める。
そこへいきなり「父」と呼びかけると、決めつけになる。

そこで**呼びかけと主題を分けた。**

| | どう書くか | 理由 |
|---|---|---|
| h1・`<title>`・meta・計算の前提・差が出ないものの説明 | **「父」「母」のまま** | 扱っている題と、計算しているモデルの記述。読み手を指していない。読み手はこの題を見て来ている |
| 読み手とその相手を指すところ | **`あなた` / `パートナー`** | カード・スライダーの下の一文・底のバー・読み上げの一文・当てはまるかどうかの説明 |

`母`ではなく`パートナー`にしてある。`あなた`と並べたときに、
片方だけ続柄になるのを避けられるため。

**呼び方を入力させない。** 以前は「呼び方」の欄を置いて名前を入れ替えられるようにしていたが、
やめた。**自分で名づけるものではないし、道具の性格が変わる。** 入力は5つだけという方針にも合う。

**それでも画面に直書きしない。** 呼び方は `LABELS` に置いて `drawLabels()` から配る。
静的な HTML に名前を書くと、変えたときにそこだけ古いまま残る
（実際、凡例・保育料の見出し・表のキャプションがそうなっていた）。
legend は続柄で固定なので、ここだけは静的な HTML に置いてある。
静的な文の中で人を指すところは `<span class="p-mother">` / `<span class="p-father">` を置く。

**1画面にしたので、続柄と二人称を混ぜるのをやめた。**
節が分かれていた頃は「入力欄の legend は続柄（`赤ちゃんのお父さま`）、結果の文は `あなた`」で
分けていた。箱が分かれていれば成り立つが、**同じ画面に両方が見えると、
同じ人が2つの名前で呼ばれる**ことになる。

いまは画面に出る呼びかけを `あなた` / `パートナー` の1組に揃えてある
（`あなたの月のお給料` / `パートナーの月のお給料` / `あなたの育休の長さ`）。
h1・`<title>`・計算の前提は `父` `母` のままで、こちらは**モデルの記述**なので変えない。

**二人称で否定形を書かない。** 「あなたが取らないと パートナーの分も出ません」は詰問になる。
事実は変えずに「取らない場合は パートナーの分も出ないので」と条件で書く。
取らない選択を否定しない方針とぶつかるため。

### 説明は畳む

**散文を先に置かない。** 上から順に、入力・答え・目安であることの一文。
「どうしてそうなるか」「当てはまらない場合」「前提」「出典」は
`details` ひとつに畳んで、読みたい人だけが開く。

**免責は「責任を負えない」の一文だけ畳まずに出す。** 畳んでよいのは理由と一覧のほう。

`summary` は既定の三角が出ない書き方をしているので、印は CSS で自前に描く。

### 同じことを2か所に書かない

**画面の中では、1つの事実に置き場を1つだけ決めてある。**

| 何を | どこに書くか |
|---|---|
| 目安であること・責任を負えないこと | 結果のすぐ下の1行 |
| 当てはまらない人 | 畳んだ中の「当てはまらない場合」（`#scope`） |
| いま画面に出していないものと、その理由 | 畳んだ中の「出していないもの」（`#not-shown`） |
| 計算の決めごと | 畳んだ中の「計算の前提」1か所 |
| 制度の版と有効期限 | 畳んだ中の「数字の根拠にした資料」1か所 |
| 入力した内容を送らないこと | 畳んだ中の先頭1か所 |
| この額が何でできているか | 結果カードの内訳の1行 |
| 3年で見た差 | 結果カードの最後の1行 |

### 「動かす」と「結果を見る」を離さない

**この道具で動かせるのは父の育休の月数だけ。** それなのに、
スライダーは1画面目、その結果は2〜3画面目にあって、**動かしても何も見えなかった。**
一時はこれを2つの仕掛けで塞いでいた——スライダーの直下に結果を出す `.slider-echo` と、
入力欄が画面から出たら底に現れる `.sticky-bar`。

**1画面に収めたので、どちらも消した。** スライダーと結果が同時に見えているなら、

## 跨ぐことが中身

**この節は計算の話で、いま画面に出ているのはこのうち「二人とも家にいる間の手取り」だけ。**
残りは `calc.js` の中で動いていて、表示だけを外してある。

```
出産手当金              →  産休中（産前42日・産後56日）。非課税
給付金の発生            →  育休中に毎月。非課税
給付金の入金            →  2か月分まとめて。最初の入金までは空白ができる
社会保険料の免除         →  産休中・育休中
所得税                  →  その年（年末調整で戻る）
住民税                  →  休業中は前年分を払い続け、翌年度に下がる
住宅ローンの審査年収      →  復職後1〜2年。前年の源泉徴収票が低いまま
保育料                  →  世帯（父母の合算）の所得割額。しかも9月に切り替わる
ふるさと納税の上限        →  寄附した年の所得で決まり、引かれるのは翌年度の住民税から
児童手当の所得判定        →  前年所得ベース（2024年10月に所得制限は撤廃）
```

既存の解説ページの多くは給付金の月額で話が終わっていて、1年で切ると「損」に見える。
2年で締めると差が縮む。その形を見せる。

とくに効くのが次の点。

1. **育児休業給付も出産手当金も非課税なので、源泉徴収票の支払金額に載らない。**
   家計には入っているのに、書類の上の年収だけが消える。気づくのは住宅ローンを申し込んだ後になる。
   **母の年収は、父が育休を取ろうと取るまいと下がる**（産休と育休は両方のシナリオにあるので）。
2. **入金までの空白は、産休から数えると一番長い。**
   母は産休に入ってから育児休業給付の最初の入金まで数か月あく。
   出産手当金も産後にまとめて申請するのが普通なので、その間給与も止まっている。
3. **保育料は世帯の市町村民税「所得割額」で決まり、9月に切り替わる。**
   4〜8月分は前年度（前々年の所得）、9〜3月分は当年度（前年の所得）。父母の合算。
4. **ふるさと納税の控除の上限は、寄附した年の所得で決まる。**
   住民税の特例分には「所得割額の20%」という上限があるので、
   育休に入る年に例年どおり寄附すると控除しきれず、自己負担がそのまま増える。
5. **休業中に支払われた賞与は、社会保険料が免除される。**
   「賞与を支払った月の末日を含んだ連続した1か月を超える育児休業等」が条件。
   ちょうど1か月では「超える」に当たらないので免除されない。
6. **収入が下がると、パートナーが配偶者控除・配偶者特別控除を受けられることがある。**
   対象になるかどうかだけ判定する。
7. **育休中は、会社の定期健康診断がない。**
   健康診断は1年に1回（労働安全衛生規則 第44条）だが、休業中は実施しなくてよく、
   復帰後に速やかに行う扱いになっている。民間の住宅ローンは団信への加入が条件のことが多く、
   加入には健康状態の告知が要る。
   **書類の上の年収が下がって見える時期と、直近の健診結果が手元にない時期が重なる。**
8. **男性は48.9%が1か月未満、79.2%が3か月未満。**
   「長く取らないといけない」という思い込みが、一番外れているところかもしれない。

## 引いた線

**出さないものを決めてあるので、勝手に足さない。**

### 差が出ないので扱わないもの

このツールは「父が育休を取るか取らないか」の差を出す道具なので、
**両方のシナリオで同じになるものは、差額には入れない。**

| 出さないもの | 理由 |
|---|---|
| **出産育児一時金と出産費用** | 育休を取っても取らなくても同額で、しかも大半は出産費用と相殺される。この問いに関係がない |
| **復職後の時短勤務と育児時短就業給付金** | 育休を取っても取らなくても時短はする。片方だけに入れると**存在しない差**を作ってしまう |
| **母の産休・育休そのもの** | 差はゼロ。ただし**水準**には効くので、両方のシナリオに同じだけ載せてある（外すのとは違う） |

### 決め打ちにして扱わないもの

| 出さないもの | 理由 |
|---|---|
| **父の1か月未満の育休** | 14日で要件は満たせるが、産後の回復期を支えられる長さではない。**制度の都合を本人の都合とすり替えない**。入力は1か月から |
| **父が生まれた日より後に取る場合** | 出生後休業支援給付金の対象期間（8週）を外れることがある。画面に注意だけ書く |
| **産後パパ育休の分割取得** | 短期取得を前提にした制度なので、1か月以上に絞った以上は要らない |
| **母の育休の延長（1歳6か月・2歳）** | 不承諾通知などの要件があり、取れるかを事前に決め打ちできない |
| **第2子の連続育休** | 標準報酬月額の固定やみなし被保険者期間の特例が絡む。いまは扱わない |
| **育休中の就業（月10日・80時間以内）** | 給与ゼロ前提で通す |

### そもそも出せないもの

| 出さないもの | 理由 |
|---|---|
| **借入可能額** | 住宅ローンの審査基準は金融機関ごとに違い、公開されていない。出したら嘘になる。出せるのは「源泉徴収票にこう載る」まで |
| **保育料の実額** | 自治体差が大きい。出すのは階層を決める数字（世帯の所得割額）と、それがどの年の所得かだけ |
| **入金の正確な日付** | 勤務先がいつ申請するかで動く。月の粒度の目安に留める |
| **賞与（ボーナス）** | 算定期間が休業と被ったときの扱いは会社ごとに大きく違い、公開された制度ではない。**MVP では入力ごと外して、計算にも入れていない**（[ボーナスを外した](#ボーナスを外した)） |
| **配偶者控除・配偶者特別控除の額** | 令和8年分の控除額の表が国税庁にまだ出ていない。**対象になるかどうかだけ判定する** |
| **高額療養費の自己負担限度額** | 令和8年8月から見直し、令和9年8月から70歳未満の区分が13段階に細分化される予定。動いている最中なので計算しない |
| **会社側の税制優遇** | くるみん・えるぼし認定による賃上げ促進税制の上乗せがあるという情報はあるが、令和8年度の税制改正で廃止される予定という話も出ていて、一次情報で確認できなかった。**助成金と認定制度だけを書き、税制には触れていない** |
| **団信に入れるかどうか** | 加入の可否は保険会社の審査で決まり、基準は公開されていない。**育休中に健康診断がないことと、団信に健康状態の告知が要ることを事実として並べるだけ**にして、可否も要否も断定していない |
| **育休がキャリアにどう影響するか** | 会社・職種・本人でまったく違うので、このツールが答えを持てない。**否定的な人を説得する機能も作らない**（論争の道具になり、性質が変わる）。書けるのは、法律で守られていることと相談先まで |
| 将来の予測 | 過去と現在の制度で計算した結果だけを並べる |
| 個別の相談の受付 | 一般的な計算に留める。社労士・FPの業務に近づかない |

課金・広告・ログイン・保存・他人のデータを預かる機能も置かない。
どれも入れた瞬間にサーバか維持工数か法的な線引きが発生する。

## 誰に当てはまらないか

**目的を絞った分、当てはまらない人がいる。画面にも書いてある。**

- 母が育休を取らない・取れない（母が主たる稼ぎ手、職場の事情など）
- ひとり親
- 自営業・フリーランスなど、雇用保険に入っていない
- 雇用保険の被保険者期間が足りない（休業開始前2年に賃金支払基礎日数11日以上の月が12か月）

**入力欄の legend は `赤ちゃんのお父さま` / `赤ちゃんのお母さま` で、続柄で書いてある。**
以前は「産休を取るほう／取らないほう」と役割で括って、同性カップルや養子縁組でも
読める形にしていたが、**何の話か分からない**という理由で続柄に戻した。
結果の文のほうは `あなた` / `パートナー` なので続柄ではない
（[読み手を「父」と呼ばない](#読み手を父と呼ばない)）。
いずれにせよ計算は上の前提に乗っているので、当てはまらない人はいる。

## 置いている前提

画面にも書いてあるが、ここにも残す。

- 出産予定日どおりに生まれるものとして扱う
- **賞与は計算に入れない**（MVP。給与だけで見る）
- 産休・育休中は給与が支払われないものとする
- 月の途中で休業に入る月の給与は暦日で日割りする
- 社会保険料は標準報酬月額で決まるので、給与を日割りしても月額は変わらない
- 出産手当金は、標準報酬月額のかわりに月給をそのまま使う（等級表には当てはめていない）
- 扶養は考慮しない（基礎控除と社会保険料控除だけ）
- 健康保険料率は協会けんぽの全国平均。都道府県で 9.44%〜10.55% の幅がある
- 住民税は単身・級地1を想定した目安。均等割・非課税限度額は自治体で変わる
- 所得税は年末調整後の年額を、その月の額面の比で割り付けている。毎月の源泉徴収額とは一致しない
- 住民税は年額の1/12を毎月置いている。実際は普通徴収（年4期）や一括徴収になることがあり、
  谷の位置は変わる
- 入金は「対象の支給単位期間が終わった翌月」に置いている。実際は勤務先の申請時期で前後する
- 育児休業給付金と出生後休業支援給付金は別々の給付金なので、それぞれ円未満を切り捨てて足す
- 保育の開始は既定で「母が復職する月」（いまは画面に出していない）
- 保育料の階層の区切りは自治体ごとに違う。出しているのは階層を決める数字だけ
- 健康診断と団信については計算していない。事実を書いているだけ

### 統計を扱うときの決めごと

**比べて競うためのものにしない。** 平均との比較や優劣は出さない。
出すのは「取った男性のうち何%がこの区分か」と「同じか短い区分の人が何%いるか」まで。

**女性の統計は出していない。** このツールの目的（父が取りやすくなること）には要らないため。

取得期間の分布は、四捨五入のため合計がちょうど100.0にならないことがある
（男性の区分は手元の抽出で100.2になる）。統計表としては通常のことだが、
気になるなら e-Stat の付属統計表第16表で突き合わせること。

### 要確認のまま残していること

**推測で埋めない。確認できるまで計算に入れない。** 画面の「計算の前提」の最後にも出している。

- **子ども・子育て支援金（令和8年4月分から 0.23%）を計算に入れていない。**
  二次情報では労使折半（本人 0.115%）とされるが、協会けんぽの一次情報では
  労使折半かどうかと、育児休業中の保険料免除の対象になるかが確認できなかった。
  `rules-2026.js` の `kodomoShienApplied` を `true` にすれば有効にできる
- 住民税の調整控除で使う「人的控除の差」を基礎控除分の5万円としている。
  令和7年度・8年度改正による所得税の基礎控除の上乗せ分が
  この差に反映されない扱いである前提。**自治体の案内で毎年確認すること**

### 点検で見つけて直した誤り

- 協会けんぽの料率の幅を「9.21%（新潟）〜10.55%（佐賀）」と書いていたが、
  令和8年度の最低は**沖縄県の 9.44%** だった。検索結果の要約をそのまま使ったのが原因
- 育児休業給付の期間に上限がなく、育休36か月と入れると36か月分給付が出ていた。
  子の年齢を持っていなかったのが原因。出産予定日を起点にしたことで解消した

## いずれ足したいもの

介護休業・病気休職など、**他の休みかたでお金がどう動くか**。
「いつ効くか」の構造は共通しているはずなので、同じ時間軸に載せられる。
いまは育児休業だけを扱っている。

## 免責

**目安を出す道具で、精度は追求していない。**
育休を取るかどうかを考えるときに、お金の動きの形を見るためのもの。
どこまで見ていないかは[置いている前提](#置いている前提)にすべて書いてある。

**この結果をもとに資産計画・借入・寄附・保険などを決めて損失が生じても、
作者は一切の責任を負えない。**
実際の金額と手続は、必ず勤務先の担当部署・お住まいの自治体・ハローワーク・
税務署などの一次の窓口で確認すること。
