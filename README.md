# やすめる

育休のお金が、育休の前後3年でどう動くかを1本の時間軸に並べる Web ツール。夫婦合算。

**育休のお金は、制度が複雑なうえに効くタイミングがバラバラで、
先が見えないまま取るかどうかを決めることになりがち。**
見えるようにして、憂いを減らして育休を取りやすくするための道具。

**取りにくさはお金だけの話ではない**ので、
「同じ立場の人がどのくらい取っているか」も出している。
比べて競うためではなく、「自分だけじゃない」と分かるため。

**取りにくさは、まわりの目のこともある。** 会社の側にも助成のしくみがあること、
不利益な扱いが法律で禁じられていること、相談先があることを事実として置いている。
**説得のための材料としては書いていない**（申請するのは会社であって本人ではないし、
「会社に教えてあげましょう」は本人に負担を移すことになる）。

## 画面の作り

**いちばん先に出すのは「育休中、毎月の手取りはこのくらい」。**
給付率67%と聞くと怖いが、非課税＋社会保険料の免除があるので手取りで見ると最初の6か月は約8割。
出生後休業支援給付金の対象ならほぼ変わらない。ここを入口にしている。

**合計の差額を入口にしない。** 開いて最初に「−171万円」が目に入る作りにしていた時期があったが、
憂いを減らすのが目的なのに恐怖から始まっていた。差額は「先に知っておくと落ち着けること」の
4枚目に、ほかの事実と並べて置いている。

読み手は30歳前後を想定している。ふだん使うアプリの見え方に寄せて、

- スマホで縦に読み進められること（横スクロールを作らない）
- 要点がカードで先に来て、こまかい表は畳んであること
- 入力は基本5つだけ見せて、残りは「あてはまれば」に畳むこと
- 税理士に相談しにくい人が読めること（専門用語には必ず言い換えを添える）
- センシティブな時期なので、押しつけず、決めつけないこと

を優先した。「損」「得」は強調せず、育休を取らない選択も否定しない書き方にしている。

> **目安を出す道具で、精度は追求していない。**
> この結果をもとに資産計画・借入・寄附などを決めて損失が出ても、補償はできない。
> 実際の金額と手続は必ず勤務先・自治体・ハローワークで確認すること。

```
給付金の発生            →  育休中に毎月
給付金の入金            →  2か月ぶんまとめて。最初の入金までは空白ができる
社会保険料の免除         →  育休中
所得税                  →  その年（年末調整で戻る）
住民税                  →  育休中は前年分を払い続け、翌年度に下がる
住宅ローンの審査年収      →  復職後1〜2年。前年の源泉徴収票が低いまま
保育料                  →  世帯（父母の合算）の所得割額。しかも9月に切り替わる
ふるさと納税の上限       →  寄附した年の所得で決まり、引かれるのは翌年度の住民税から
児童手当の所得判定       →  前年所得ベース
```

**跨ぐことが中身。** 既存の解説ページの多くは給付金の月額で話が終わっていて、
1年で切ると「損」に見える。2年で締めると差が縮む。その形を見せる。

とくに効くのが3つ。

1. **育児休業給付は非課税なので、源泉徴収票の支払金額に載らない。**
   家計には入っているのに、書類の上の年収だけが消える。気づくのは住宅ローンを申し込んだ後になる。
2. **保育料は世帯の市町村民税「所得割額」で決まり、9月に切り替わる。**
   4〜8月分は前年度（前々年の所得）、9〜3月分は当年度（前年の所得）。
   父母の合算なので、夫婦の育休の取り方がそのまま効く。
3. **給付金の入金は2か月ぶんまとめて。**
   支給申請は原則2つの支給単位期間をまとめて行うので、育休に入ってから最初の入金まで空白ができる。
   給与も止まっているので、そこを貯蓄でしのぐ必要がある。
4. **ふるさと納税の控除の上限は、寄附した年の所得で決まる。**
   住民税の特例分には「所得割額の20%」という上限があるので、
   育休に入る年に例年どおり寄附すると控除しきれず、自己負担がそのまま増える。
5. **育休中に支払われた賞与は、社会保険料が免除される。**
   「賞与を支払った月の末日を含んだ連続した1か月を超える育児休業等」が条件。
   課税はされるので源泉徴収票には載るが、健保・厚年がかからないぶん手取り率が高い。
6. **育休で所得が下がると、パートナーが配偶者控除・配偶者特別控除を受けられることがある。**
   見落とされやすい「得する側」の効果。対象になるかどうかだけ判定する。

7. **育休中は、会社の定期健康診断がない。**
   健康診断は1年に1回（労働安全衛生規則 第44条）だが、休業中は実施しなくてよく、
   復帰後に速やかに行う扱いになっている。ここが住宅ローンにつながる。
   民間の住宅ローンは団信への加入が条件になっていることが多く、
   加入には健康状態の告知と保険会社の審査があって、
   金融機関や借入額によっては健康診断の結果を求められる。
   **書類の上の年収が下がって見える時期と、直近の健診結果が手元にない時期が重なる。**
   計算はしていない。事実として書いてあるだけ。

8. **取りにくさは金額面だけではない。**
   厚生労働省の調査から、取得率と**取得期間の分布**を出している。
   男性は48.9%が1か月未満、79.2%が3か月未満。
   「長く取らないといけない」という思い込みが、いちばん外れているところかもしれない。

そして**子育て系の給付は所得制限を外す方向に動いている。**
児童手当は2024年10月に、高等学校等就学支援金は令和8年4月に所得制限が撤廃された。
「前年の所得で判定される」と思い込んでいると間違える。残っているものを表にした。

## 動かす

サーバもビルドも要らない。ただし ES モジュールを使っているので、
`file://` で直接開かず、適当な静的サーバ越しに開く。

```sh
python3 -m http.server 8000
# → http://localhost:8000/
```

計算はすべてブラウザの中で終わる。外部への通信はゼロ（出典のリンクを踏んだときだけ）。

## テスト

```sh
node test.mjs
```

**手で計算した値と実装の出力を突き合わせる。** 期待値は全部手計算で、
計算式を各項目のコメントに残してある。

数値を変えるときは、**まず手計算をやり直してコメントを書き換え、そのあとで実装を直す。**
逆をやると実装の間違いが期待値に写る。

## ファイル

| ファイル | 中身 |
|---|---|
| `rules-2026.js` | **制度の数値。ここだけ隔離してある**。全項目に出典と適用期間つき |
| `calc.js` | 計算ロジック。制度の数値を直接書かない（必ず `rules` から受け取る）。1人ぶんの `simulate` と、共通の時間軸に載せて合算する `simulateHousehold` |
| `app.js` | 画面。入力の読み取り、SVG のチャート、表 |
| `index.html` / `style.css` | 1画面。ライト／ダーク両対応 |
| `test.mjs` | 手計算リファレンスとの突合 |

`rules-2026.js` を `.json` ではなく `.js` にしてあるのは、`fetch` を挟まずに
ブラウザからも `node` のテストからも同じものを読むため。中身は素のデータで、
ロジックは持たせていない。

## 更新のしかた（年1回）

制度の改定は年1回に集中している。**`rules-2026.js` だけを差し替えれば済む形にしてある。**

| 何が | いつ変わる |
|---|---|
| 育児休業給付の上限額・下限額 | 毎年8月1日 |
| 雇用均等基本調査（取得率・取得期間の分布） | 毎年7月ごろ公表 |
| 協会けんぽの健康保険料率・介護保険料率 | 毎年度（3月分から） |
| 雇用保険料率 | 毎年度（4月から） |
| 所得税・住民税の控除や税率 | 税制改正のたび |

`rules-2026.js` の `validUntil` を過ぎたら数値を確認し直す。
**出典を開いて確認すること。記憶で書き換えない。**

実際、作っているときに Web に出回っていた支給上限額 323,811円 を拾いかけたが、
これは前年度の値で、公式パンフレット（2026年8月版）の現行値は 332,454円（30日・67%）だった。

更新したら `node test.mjs` を回す。手計算の期待値も一緒に直すこと。

## 引いた線

**出さないものを決めてあるので、勝手に足さない。**

| 出さないもの | 理由 |
|---|---|
| **借入可能額** | 住宅ローンの審査基準は金融機関ごとに違い、公開されていない。出したら嘘になる。出せるのは「源泉徴収票にこう載る」まで |
| **保育料の実額** | 自治体差が大きい。出すのは階層を決める数字（世帯の所得割額）と、それがどの年の所得かだけ |
| **入金の正確な日付** | 勤務先がいつ申請するかで動く。月の粒度の目安に留める |
| **育休中の賞与の額** | 算定期間が育休と被ったときの扱いは会社ごとに大きく違う（部署の平均評価にする、期間で按分する、一律で減らす など）。**公開された制度ではないので計算せず、割合を入力してもらう** |
| **配偶者控除・配偶者特別控除の額** | 令和8年分の控除額の表が国税庁にまだ出ていない（令和7年分以降のものしかなく、令和8年度改正で所得区分も動いている）。**対象になるかどうかだけ判定する** |
| **高額療養費の自己負担限度額** | 令和8年8月から見直し、令和9年8月から70歳未満の区分が13段階に細分化される予定。動いている最中なので計算しない |
| **会社側の税制優遇** | くるみん・えるぼし認定による賃上げ促進税制の上乗せがあるという情報はあるが、令和8年度の税制改正で廃止される予定という話も出ていて、一次情報で確認できなかった。**助成金と認定制度だけを書き、税制には触れていない** |
| **団信に入れるかどうか** | 加入の可否は保険会社の審査で決まり、基準は公開されていない。必要な書類も金融機関ごとに違う。**育休中に健康診断がないことと、団信に健康状態の告知が要ることを事実として並べるだけ**にして、可否も要否も断定していない |
| **育休がキャリアにどう影響するか** | 会社・職種・本人でまったく違うので、このツールが答えを持てない。**否定的な人を説得する機能も作らない**（論争の道具になり、性質が変わる）。書けるのは、法律で守られていることと相談先まで |
| 将来の予測 | 過去と現在の制度で計算した結果だけを並べる |
| 個別の相談の受付 | 一般的な計算に留める。社労士・FPの業務に近づかない |

課金・広告・ログイン・保存・他人のデータを預かる機能も置かない。
どれも入れた瞬間にサーバか維持工数か法的な線引きが発生する。

## 置いている前提

画面にも書いてあるが、ここにも残す。

- 育休は月の初日に始まり、支給単位期間は暦月と一致するものとして扱う
- 育休中は給与も賞与も支払われないものとする
- 扶養は考慮しない（基礎控除と社会保険料控除だけ）
- 健康保険料率は協会けんぽの全国平均。都道府県で 9.44%〜10.55% の幅がある
- 住民税は単身・級地1を想定した目安。均等割・非課税限度額は自治体で変わる
- 育休中に支払われた賞与は、育児休業給付金の減額の対象にしていない
  （3か月を超える期間ごとに支払われるものとして扱っている）
- 賞与の社会保険料の免除は「賞与月が育休期間に入っていて、かつ育休が2か月以上」で判定している。
  一次情報の要件は「支払月の末日を含む連続1か月超」で、これを月単位で近似したもの
- 所得税は年末調整後の年額を12で割って月ごとに置いている。毎月の源泉徴収額とは一致しない
- 毎月の折れ線には**賞与を入れていない**。賞与月の山が縦軸を占めて、
  給付率が落ちる段差と住民税が下がる段差が見えなくなるため。賞与は表と合計差額には入っている
- 入金は「対象の支給単位期間が終わった翌月」に置いている。実際は勤務先の申請時期で前後する
- 保育の開始は既定で「遅いほうが復職する月」。画面で変えられる
- 保育料の階層の区切りは自治体ごとに違う。出しているのは階層を決める数字だけ
- 健康診断と団信については計算していない。事実を書いているだけ

### 統計を扱うときの決めごと

**比べて競うためのものにしない。** 平均との比較や優劣は出さない。
出すのは「取った人のうち何%がこの区分か」と「同じか短い区分の人が何%いるか」まで。

取得期間の分布は、四捨五入のため合計がちょうど100.0にならないことがある
（男性の区分は手元の抽出で100.2になる）。統計表としては通常のことだが、
気になるなら e-Stat の付属統計表第16表で突き合わせること。

### 要確認のまま残していること

**推測で埋めない。確認できるまで計算に入れない。** 画面の免責にも同じ内容を出している。

- **子ども・子育て支援金（令和8年4月分から 0.23%）を計算に入れていない。**
  二次情報では労使折半（本人 0.115%）とされるが、協会けんぽの一次情報では
  労使折半かどうかと、育児休業中の保険料免除の対象になるかが確認できなかった。
  `rules-2026.js` の `kodomoShienApplied` を `true` にすれば有効にできる
- 住民税の調整控除で使う「人的控除の差」を基礎控除分の5万円としている。
  令和7年度・8年度改正による所得税の基礎控除の上乗せ分が
  この差に反映されない扱いである前提。**自治体の案内で毎年確認すること**

### 点検で見つけて直した誤り

一次情報を取り直す点検で1件見つかった。**二次情報のまま置いていたところに出た。**

- 協会けんぽの料率の幅を「9.21%（新潟）〜10.55%（佐賀）」と書いていたが、
  令和8年度の最低は**沖縄県の 9.44%** だった。検索結果の要約をそのまま使ったのが原因

## いずれ足したいもの

介護休業・時短勤務・病気休職など、**他の休みかたでお金がどう動くか**。
「いつ効くか」の構造は共通しているはずなので、同じ時間軸に載せられる。
いまは育児休業だけを扱っている。

## 免責

**目安を出す道具で、精度は追求していない。**
育休を取るかどうかを考えるときに、お金の動きの形を見るためのもの。

扶養・各種控除・住宅ローン控除・医療費控除などは反映していない。
健康保険料率は全国平均で、住んでいる都道府県の実際の料率とは違う。
住民税は単身・級地1を想定した目安。入金の時期は勤務先の申請時期で前後する。

**この結果をもとに資産計画・借入・寄附・保険などを決めて損失が生じても、
作者は一切の責任を負えない。**
実際の金額と手続は、必ず勤務先の担当部署・お住まいの自治体・ハローワーク・
税務署などの一次の窓口で確認すること。
